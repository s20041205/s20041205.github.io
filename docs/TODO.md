## 新功能

### 🟡 自動記帳：電子發票載具

用手機條碼載具，從財政部電子發票平台抓取消費發票（店家、金額、品項明細）自動記帳。

**可行性**
- 財政部有官方 API（[電子發票應用 API 規格](https://www.feam.scu.edu.tw/uploads/5be58015e6782bae49c1ff627a2bad35.pdf)），
  查詢載具發票需帶 **AppID + 手機條碼 + 驗證碼**
- AppID 須向財政部財政資訊中心申請、**審查通過**才核發；個人目前能否申請需先確認
- 若能取得：GAS 每日觸發器以 `UrlFetchApp` 抓前一天發票 → 寫入「待確認」清單
- 若無法取得：退而求其次，定期從電子發票平台下載載具消費明細 CSV，在後台上傳匯入

**設計要點**
- 發票只有店家與品項，**沒有記帳類別** → 先進「待確認」清單，不直接寫入 `active`
- 依歷史記錄自動推薦類別（同店家最常用的大類 / 小類），App 內一鍵確認
- 去重鍵：發票號碼（存入 `RecurringKey` 類似的欄位）
- 驗證碼屬敏感資料，存 Script Property，不可進前端或 git

### 🟡 自動記帳：信用卡刷卡通知

刷卡後由簡訊 / 通知自動產生記帳。

**可行做法（依穩定度）**
1. **Email 通知 + GAS 讀 Gmail（最推薦）**：多數銀行可設定刷卡 email 通知。GAS 觸發器以
   `GmailApp` 搜尋銀行通知信、解析金額 / 商店 / 時間，完全在伺服器端，不依賴手機
2. **iPhone 捷徑自動化**：「收到訊息時（內含特定文字）」→ 捷徑擷取金額 / 商店 →「取得 URL 內容」
   POST 到 GAS
3. **Android**：MacroDroid / Tasker 監聽簡訊或銀行 App 通知 → HTTP POST 到 GAS

**設計要點**
- 每家銀行訊息格式不同，需逐家寫解析規則
- 同一筆消費可能同時有**刷卡通知與電子發票** → 兩者都進「待確認」清單，以日期 + 金額配對合併
- 簡訊 / 通知只有商店名稱，類別同樣靠歷史推薦 + 人工確認
- 需先完成「GAS 存取驗證」，否則任何人都能偽造寫入

### 共用基礎：「待確認」清單

上面兩項都需要：新分頁 `pending`（來源、日期、金額、店家、明細、推薦類別、外部 ID、狀態），
App 新增「待確認」頁面，可逐筆調整類別後確認寫入 `active`，或忽略。

## Sheets 重整（低優先）

**背景**：舊版原始碼曾硬編碼試算表 URL，現仍留在 git 歷史中。

**目前狀態（2026-10）**
- 試算表已設為「限制存取」，他人拿到 ID 也無法開啟
- GAS 不再信任前端傳入的 `sheetUrl`，舊部署已全部封存，只剩單一新部署

**若要徹底處理**
1. 複製現有試算表 → 取得全新 ID
2. Apps Script 執行 `setSpreadsheetId('<新ID>')`（若 GAS 綁定在舊試算表，需在新試算表重建專案並重新部署）
3. 更新 Secret `SHEET_URL`（若重建 GAS，也要更新 `SCRIPT_WRITE_URL`、`SCRIPT_READ_URL`）
4. 確認新試算表結構符合 [sheets-schema.md](sheets-schema.md)
5. 選擇性以 `git filter-repo` 清除 git 歷史中的舊 URL
