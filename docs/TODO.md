## 修正

### 🔴 GAS 存取驗證

`/exec` 網址寫在公開的 `config.js`，GAS 又是匿名存取，任何人都能讀 / 改 / 刪全部帳目
（2026-10 實測不需密碼即可讀取 3000 筆）。`dashboardPassword` 也在 `config.js` 裡公開可見。

- 存取碼存於 Script Property，GAS 每個請求比對，不符即拒絕
- 每台手機首次使用輸入一次，存於 `localStorage`，所有請求帶上
- 移除 `config.js` 的 `dashboardPassword`（與 Secret `DASHBOARD_PASSWORD`）
- **待決定**：存取碼是否與後台密碼共用

> 這是下方「發票載具」「刷卡通知」等自動寫入功能的前提。

### 🔴 後台刪除後列號錯位

`deleteRecord` 以列號刪除，下方列會上移，但 [js/dashboard.js](../js/dashboard.js) 只從清單移除
被刪的那筆，其他記錄的 `rowNum` 未更新 → 接著編輯較新的記錄會改到錯的列。

- 刪除後重新載入清單
- GAS `updateRecord` / `deleteRecord` 改寫前比對該列 `Update` 時間戳，不符即拒絕

## 新功能

### 🟡 自動記帳（分層設計）

外部來源都**沒有記帳類別**，一律先進「待確認」清單，人工確認後才寫入 `active`。
前提：先完成「GAS 存取驗證」，否則任何人都能偽造寫入。

| 層 | 來源 | 時效 | 負責 |
|----|------|------|------|
| 即時 | 信用卡刷卡 email 通知 | 刷卡後數分鐘 | 大部分消費：金額 + 商店 |
| 對帳 | 電子發票「消費發票彙整通知」email | 每月一次 | 與刷卡紀錄配對補上品項；找出漏記（現金 + 載具） |
| 手動 | App 表單 | 隨時 | 無任何通知的消費 |

> 發票本來就不是即時資料：店家依規定 48 小時內上傳，即使用 API 也是 1–2 天後才查得到。

#### 1. 刷卡 email 通知（先做）

- 到常用信用卡銀行開啟刷卡 email 通知，取得一封範例信確認格式
- GAS 觸發器（如每 15 分鐘）以 `GmailApp` 搜尋銀行通知信，解析金額 / 商店 / 時間 → `pending`
- 每家銀行格式不同，逐家寫解析規則；以 Gmail message ID 去重，處理完加標籤
- 依卡片持有人對應使用者（Jerry_Hu / Alice_Lin）
- 備案（不走 email 時）：iPhone 捷徑「收到訊息時」或 Android MacroDroid / Tasker 監聽簡訊 / 銀行 App 通知 → POST 到 GAS

#### 2. 發票月底對帳

- 手機條碼完成信箱驗證並開啟「消費發票彙整通知」，取得一封範例信確認格式（內文或附件、是否含品項）
- GAS 解析後進 `pending`，以**日期 ± 2 天 + 金額**與既有刷卡項目 / `active` 記錄配對：
  - 配對到 → 補上發票號碼與品項明細，不重複記帳
  - 配對不到 → 新增為待確認（多半是現金或漏記）
- 去重鍵：發票號碼
- 若月底對帳太慢：申請財政部 AppID（[電子發票應用 API](https://www.feam.scu.edu.tw/uploads/5be58015e6782bae49c1ff627a2bad35.pdf)，
  須審查，個人能否申請待確認），改為每日查詢。驗證碼存 Script Property，不可進前端或 git

#### 3. 「待確認」清單（共用基礎）

**資料**：新分頁 `pending`

`Id, Source(card/invoice), ExternalId, Date, Price, Store, Items, Name, SuggestTopclass,
SuggestSubclass, MatchedId, Status(pending/confirmed/ignored), CreatedAt`

**類別推薦**：同店家在 `active` 最常用的大類 / 小類；首次出現的店家留空待人工選

**後台介面**

- 位置：後台新增「待確認」Tab，**排第一個**，Tab 上顯示筆數徽章；首頁「後台」連結也顯示筆數
  - 待決定：放在後台 Tab，或獨立頁面 `review.html`（後台圖表多、載入較慢；獨立頁打開較快）
- 版面：**卡片式**（手機友善），不用目前「近期修改」的 10 欄表格
- 每張卡片：
  - 來源圖示（💳 刷卡 / 🧾 發票）、日期、金額、商店；發票品項可展開
  - 大類 / 小類下拉**預先帶入推薦**、使用者、標記、店家 / 項目可直接改
  - 已配對的刷卡 + 發票顯示為同一張卡片
  - 按鈕：**確認**（寫入 `active`）/ **忽略**
- 批次：勾選多筆 →「全部確認」（適合推薦類別都正確時）
- 確認後卡片直接從清單消失，不整頁重新載入

#### 連帶調整

- 「近期修改」Tab 改用同一套卡片式編輯元件（目前寬表格在手機上難操作）

## Sheets 重整（低優先）

**背景**：舊版原始碼曾硬編碼試算表 URL，現仍留在 git 歷史中。

**目前狀態（2026-10）**
- 試算表已設為「限制存取」，他人拿到 ID 也無法開啟
- GAS 不再信任前端傳入的 `sheetUrl`，舊部署已全部封存，只剩單一新部署

**若要徹底處理**
1. 複製現有試算表 → 取得全新 ID
2. Apps Script 執行 `setSpreadsheetId('<新ID>')`（若 GAS 綁定在舊試算表，需在新試算表重建專案並重新部署）
3. 更新 Secret `SHEET_URL`（若重建 GAS，也要更新 `SCRIPT_WRITE_URL`、`SCRIPT_READ_URL`）
4. 確認新試算表結構符合 [sheets-schema.md](sheets-schema.md)
5. 選擇性以 `git filter-repo` 清除 git 歷史中的舊 URL
